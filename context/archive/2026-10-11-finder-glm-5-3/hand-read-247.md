### pr247-01#F5

`scripts/prod-result-dimensions.py:98-113` · minor · correctness

Description:

```text
The script claims it 'never fetches a whole image', but urllib will happily read a 200 response where the server ignored the Range header; `raw = r.read()` then downloads the entire object, so the safety contract is unenforced. Also, 2048 bytes is often too small for phone JPEGs whose EXIF (with embedded thumbnail) precedes the SOF marker, causing them to fall into 'header not recognised' — and the final CONFIRMED verdict is printed even when `unreadable > 0`, so systematic false-unreadables can silently skew the census conclusion.
```

Suggestion:

```text
Check `r.status == 206` (or cap the read, e.g. `r.read(32768)`), increase the range to 16–32 KiB, and only print CONFIRMED when `unreadable == 0` (otherwise flag the conclusion as provisional).
```

### pr247-01#F6

`scripts/prod-result-dimensions.py:118-130` · nit · correctness

Description:

```text
The JPEG byte scanner doesn't handle 0xFF padding followed by 0x00 or TEM (0x01), and a literal 0xFF marker byte falls into the length-skip branch with a garbage length, desynchronizing the scan. Fine for well-formed files, but the census conclusion rests on this parser.
```

Suggestion:

```text
Skip 0xFF fill bytes and marker 0x01 explicitly, and bail out of the loop when the segment length read would take `i` past the buffer instead of continuing with garbage.
```

### pr247-02#F4

`scripts/prod-result-dimensions.py:84-101` · minor · correctness

Description:

```text
Header parsers can raise instead of returning None: the PNG branch does `struct.unpack('>II', raw[16:24])` without a length check (a short ranged response crashes the census loop with struct.error), and the JPEG scanner treats 0xFF fill bytes as a length-bearing marker, desyncing the scan. Since the whole loop has no try/except around parsing, one malformed object aborts the entire census.
```

Suggestion:

```text
Validate `len(raw) >= 24` before the PNG unpack, handle JPEG 0xFF fill bytes, and wrap the `dimensions()` call in the existing unreadable path so a parse failure counts as unreadable rather than crashing.
```
