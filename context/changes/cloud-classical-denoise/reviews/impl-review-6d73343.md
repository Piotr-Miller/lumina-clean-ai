## Findings

### F1 — The published audit stops re-deriving the verdict once the change is archived

- **Severity**: ⚠️ WARNING
- **Impact**: 🔎 MEDIUM — real tradeoff; pause to reason through it
- **Dimension**: Safety & Quality
- **Location**: scripts/s20/common.py:32, scripts/s20/evidence.py:125-156
- **Detail**: The plan's Desired End State says that, from a checkout alone, `gate.py --audit` re-derives the verdict from committed metadata. Every evidence path is hard-coded under `EVAL = "context/changes/cloud-classical-denoise/evaluations"` (`common.py:32`), and so are `CALIBRATION_REL` (`evidence.py:34`), the `pointers.py` targets and the documented commands (`gate.py:4-5`, `:393`, `step1-audit/README.md`). `/rune-archive` moves the folder to `context/archive/<date>-cloud-classical-denoise/`, and the audit then reads paths that no longer exist. Repointing `EVAL` would not be enough. `require_write_once` counts the commits of `git log --follow -M100%` (`evidence.py:132`), and that follows an exact `git mv`, so the archive commit would most likely count as a second touch of every seal and the freeze, and the audit would refuse. That rename behaviour was argued from git's semantics; a scratch-repo test of it was not permitted in this session. The reproduction claim therefore has a shelf life that ends at archive, and nothing says so. The verdict itself is not affected: it was derived and committed at 0b244bd while the paths were live.
- **Fix A ⭐ Recommended**: Say so where the claim is made: in `step1-audit/README.md` (and the plan's Desired End State note), state that `--audit` reproduces at the pre-archive commit, give that commit as the one to check out (`git worktree add <dir> <sha>`), and record the master SHA after the merge.
  - Strength: No change to rule files after the verdict, so the provenance chain the gate relied on stays as it was; costs a few lines in a folder this change owns.
  - Tradeoff: Reproduction needs a historical checkout rather than today's tree.
  - Confidence: HIGH — the paths are hard-coded, verified by reading `common.py` and `evidence.py`.
  - Blind spot: The SHA has to be written after the rebase-merge (SHAs change), so it is one more post-merge write.
- **Fix B**: Make the tools resolve the evaluations folder in either tree, and have `require_write_once` ignore a commit that only renames the path with identical content.
  - Strength: `--audit` keeps working on current master after the archive.
  - Tradeoff: Edits `RULE_FILES` after the verdict, and loosens the write-once rule the F11 fix tightened; both need their own tests and a re-review.
  - Confidence: MED — the rename exemption has to tell a pure move from a replaced seal.
  - Blind spot: AGENTS.md forbids skills writing to `context/archive/`; the audit only reads, but any later tool change that writes would hit that rule.
- **Decision**: FIXED — Fix A, recorded in plan.md § Desired End State and change.md Notes (2026-11-09), naming the reproduction point as the archive commit's parent, so no post-merge SHA write is needed; siblings: step1-audit/README.md n/a (generated by gate.py; a hand edit would diverge from the tool's output), step1-gate.md n/a (generated, and 6.6's acceptance surface), gate.py:393 n/a (rule file; editing it after the verdict is Fix B); reopened: none (no Manual row's surface edited)
