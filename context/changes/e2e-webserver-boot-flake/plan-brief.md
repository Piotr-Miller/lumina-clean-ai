# e2e Flake Evidence Closure — Plan Brief

> Full plan: `context/changes/e2e-webserver-boot-flake/plan.md`
> Frame brief: `context/changes/e2e-webserver-boot-flake/frame.md`

## What & Why

From the frame: the boot flake this change was named for is resolved (#152 evidence + #153 pin —
record and close it), and the live flake — the seed sign-in POST returning non-2xx — is currently
**unfalsifiable because the spec and job discard the response status, body, and request-level
server evidence** at the moment of failure. This plan records the resolved history and installs
the capture so the next occurrence names its layer.

## Starting Point

Three documented failure signatures; two resolved (wrangler ProxyWorker crash → pinned 4.113.0;
install timeout → `--with-deps` dropped), one live and evidence-less. The trace that would have
diagnosed the live one was generated by Playwright and never uploaded — the CI artifact lists a
`playwright-report/` directory that has never existed (no reporter configured) and omits
`test-results/` where traces actually land.

## Desired End State

A future e2e failure of any of the six response asserts prints label + status + final URL + a
bounded body snippet straight in the CI console, with the full trace one artifact-download away.
The written record (change.md, lessons.md) matches reality, including when the wrangler pin may
move.

## Scope

**In scope:** change.md resolution record; lessons.md wrangler-unpin lesson (with the ≥20-run probe
definition); shared `expectOkResponse` helper at six call sites; env-conditional reporter + html;
`trace: "retain-on-failure"`; failure artifact incl. `test-results/` plus a flaky-evidence upload
step; a hermetic Vitest test for the failure-message path.

**Out of scope:** any retry/timeout/hardening change; middleware request logging; wrangler
bump/unpin; diagnosing or fixing signature 3 itself.

## Architecture / Approach

Phase 1 is prose (record while fresh). Phase 2 is capture plumbing: one new helper in
`tests/e2e/helpers/` (the tree's documented-helper convention), mechanical adoption at six call
sites, one config line, one CI path line. No assertion semantics change anywhere.

## Phases at a Glance

| Phase                                | What it delivers                                                              | Key risk                                                                                    |
| ------------------------------------ | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 1. Record the resolved signatures    | Accurate change.md + durable unpin criterion                                  | Prose overclaims beyond evidence — keep to frame.md's verdicts                              |
| 2. Make the next occurrence readable | Enriched failure messages + traces in the artifact, incl. retry-healed flakes | Trace-on-every-attempt adds minor runtime; flaky-upload step must stay silent on clean runs |

**Prerequisites:** none — both phases land on a normal PR; the PR's own e2e job validates phase 2.
**Estimated effort:** one short session, single PR.

## Open Risks & Assumptions

- The enriched evidence may still be layer-ambiguous (e.g., bare 500, empty body) — the declined
  middleware request log is the pre-identified escalation, requiring a new decision.
- Signature 3 may not recur for a long time; the capture only pays off at the next occurrence.

## Success Criteria (Summary)

- The next sig-3-class failure is diagnosable from the CI console + one artifact download.
- change.md and lessons.md accurately record what is resolved, what is live, and when the wrangler
  pin may move.
- Zero behavior change: same assertions, same gates, all six call sites green on the PR.
